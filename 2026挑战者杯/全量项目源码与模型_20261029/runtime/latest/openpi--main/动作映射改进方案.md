# 双臂动作跟随改进方案（第二版）：以实测成功率 ≥99% 为发布条件

日期：2026-10-21  
适用：当前用户、真人摄像头输入、双臂 MuJoCo 动作跟随、拇指—食指夹爪控制。  
状态：方案复核完成；以下新增功能仍待实施，不代表模型已经达到99%。第一版保存在同目录 before_v2 文件中。

## 1. 本方案怎样指导实施

按 P0→P6 顺序修改，每个阶段都有修改入口、通过条件和失败后的处理。最终只有通过第10节的独立验收，才能发布“指定工作范围内成功率至少99%”的结论。

**按步骤实施可以建立完整的改进与验证过程，但不能预先保证当前单目设备一定达到99%。** 单目存在遮挡与深度歧义；信息不可观测时，仅靠滤波无法补齐。第12节明确软件未达标后如何继续改进。

本轮指标是人体动作跟随成功率，不是自主抓取成功率，也不是 BC 或 π0.5 训练结果。机器人仍完全在仿真中运行。

## 2. 上一版需要纠正的内容

| 原建议或结论 | 本版修正 |
|---|---|
| 把原始轨迹大跳变直接认定为机器人动作错误 | 分开检查原始估计、接收观测、IK目标和实际关节；原始异常只是待核验候选 |
| 四元数改符号可以解决180°翻腕 | q与−q表示同一旋转；改符号只处理表示连续性，不能修复模型真的估错的姿态 |
| 指尖距离/二维掌宽与视角无关 | 只部分抵消尺度；侧掌、透视及遮挡仍会造成误判 |
| 姿态权重设为0就能保持手腕 | 必须保留明确的相对前臂腕姿态或腕关节参考及连续性项 |
| 丢手后自动张爪 | 丢失表示未知；短时保持、长时暂停相关更新，不因丢手自行释放 |
| 多加几层平滑、连续三帧确认 | 按来源时间计时并测总延迟；重复帧不得积累证据，禁止未经比较叠加滤波 |
| 默认模式可验证完整腕部动作 | 当前默认 twist 固定后两个腕关节；完整腕部目标须验证 full 模式 |
| 检测丢失就剔除出测试分母 | 输入范围由独立审核确定；人手清楚入画而检测失败必须计入 |
| 990/1000能证明真实成功率≥99% | 只有点估计99%；单侧95%精确下界约98.31% |
| 反复调到同一验收录像全过 | 失败集转为回归；新版本须使用未见数据，控制重复正式验收次数 |

四元数等价性依据：[SciPy Rotation 文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.transform.Rotation.as_quat.html)。

### 2.2 已有能力与实际缺口

已有代码具备：同帧人体/手部ROI并行、约5 Hz全图找回、One Euro滤波、左右一对一关联、方向IK、限位限速、物理/显示分离及异步避碰。应在这些基础上改进。

新工作重点是：躯干基准质量、分模块观测状态、捏合标定、full腕姿态的异常恢复、独立真值和实际响应评测。

## 3. 固定99%对应的任务

### 3.1 第一轮发布范围

- 当前用户的个人标定版本。其他用户须补充独立测试，不能直接继承99%结论。
- 一台固定人体RGB摄像头，初始1280×720、目标30 FPS；实际采集帧率另行记录。
- 原始图像不镜像，仅预览镜像；肩肘腕及双手在已标定活动框内，正常室内照明。
- 包含抬臂、弯肘、前后伸手、掌心相对、前臂旋转、腕部屈伸/偏摆、左右分别捏合/松开。
- 支持的距离、动作速度、手部有效像素及机器人可执行范围由开发试验确定，正式验收前冻结，失败后不能临时缩小。
- 短时部分遮挡作为必须测试场景。持续完全出画/完整遮挡超出约定时长的情形，作为单列压力测试；不得把检测器自己的失败当作出画证据。

仿真机器上的胸部/腕部相机观察的是仿真世界，不能代替拍摄真人的摄像头，也不能凭仿真状态补出真人动作。

### 3.2 固定Episode

正式测试每个Episode固定15秒，准备、校准在其开始前完成。每段含双臂位置变化、弯肘、腕向变化，以及左右各2次“捏合→松开”，总计8个开/合边沿。动作顺序、位置、速度按预先冻结的随机分布生成。

提示时刻不能当成人实际执行的真值时刻。实际动作及事件时刻由参考记录确定。测试开始后的失败不能重新划为准备阶段。

所有条件同时通过才算成功。崩溃、无法完成动作、算法暂停过久或缺关键日志均不能记成功。输入不合格必须由独立的原图/采集条件审核证明，保留所有开始的尝试及排除理由。

### 3.3 每段完整通过条件

下表是待冻结的工程验收容差，并非当前实测能力；若需调整，应在正式验收前完成。

| 项目 | 通过条件 | 如何测量 |
|---|---|---|
| 左右身份 | 无错误交换进入控制 | 解剖左右标签与实际控制侧对照 |
| 上臂/前臂方向 | 误差P95≤10°；误差>20°不能连续超过100 ms | 独立人体参考经固定映射，与机器人实际连杆方向比较 |
| 完整腕部朝向 | SO(3)角误差P95≤15°；误差>30°不能连续超过100 ms | 同一坐标系内完整旋转差，不能只看掌法向 |
| 静止抖动 | 指定静止段肘角标准差≤3°；腕姿态相对均值RMS≤5° | 实际机器人状态，同时要求绝对偏差达标 |
| 夹爪边沿 | 8个全部正确、一一对应，无额外开合 | 左/右、开/合分别标注统计 |
| 夹爪响应 | 事件至实际夹爪运动起始≤150 ms；≤300 ms进入预定开/闭区间 | 实际夹爪关节或开度，不只看命令 |
| 跟随时滞 | 独立参考至实际机器人估计时滞≤150 ms | 同步时间及冻结的估计方法 |
| 观测可用性 | 双侧所需观测同时可用时间≥99%；最长不可用段≤200 ms | 完整墙钟时间轴，缺失/拒绝/过期都不可用 |
| 执行完整性 | 无非有限值、穿模、自碰撞、超限或持续无解 | 物理接触、实际状态、规划状态及残差 |

重复使用旧结果不算新的有效观测。可用性的“过期”上限也应在开发阶段冻结。

同时报告同一时刻误差与固定延迟补偿后的误差。补偿≤150 ms，数值在开发阶段确定；不能逐段寻找最有利的时间偏移。夹爪事件按原始同步时间判定。

机器人与人不是相同构型：固定映射应比较方向/末端姿态，不应直接逐关节复制角度。避碰绕行导致的偏离也计入跟随误差；稳定却一直跟不上不算成功。

## 4. 先修接口、躯干基准与左右身份

### 4.1 输出分层观测

每侧观测包应提供以下信息，旧数据格式需保持可读：

~~~text
source_seq, t_source, t_read_end, t_infer_done
side: anatomical_left / anatomical_right
upper_direction, fore_direction, palm_rotation_local, pinch_ratio
quality: torso / arm / palm / pinch / association
state: TRACKING / HOLD / REACQUIRING / LOST
reason_codes, last_accepted_source_time, calibration_id
~~~

`palm_rotation_local` 统一定义为相对前臂的右手系旋转矩阵：`R_forearm.T @ R_palm`，角度量一律使用弧度；如需相对躯干或世界坐标的腕姿态，必须使用另一个明确命名的字段，禁止复用此字段。

进入任何滤波、候选生成或 `dt` 计算前，先校验 `source_seq` 与 `t_source` 严格递增。重复或倒序帧记录 `NON_MONOTONIC_SOURCE`，不得更新滤波器和状态机；时间间隔过大则进入重获流程，不能把大 `dt` 当作正常连续运动。

质量分数在标定前只是工程量，不是“正确概率”。现有candidate score取自handedness分类，不能代表指尖定位精度；不得假设模型提供可靠逐指尖置信度。[MediaPipe输出定义](https://ai.google.dev/edge/api/mediapipe/python/mp/tasks/vision/HandLandmarkerResult)

记录五层数据：原始估计、接收观测、IK期望、执行器命令、实际关节。某层首次出现偏差，就先修该层。

### 4.2 躯干基准：坐姿/髋部出画是优先排查项

当前human_wrist使用双肩和双髋构架，但可见度条件未覆盖髋部23/24。有限坐标不代表可靠估计，错误基准会同时影响双臂。

实施步骤：

1. 标定肩宽、躯干轴、左右骨长及基准方向；所有参与构架的点都检查质量和几何退化。
2. 髋部短时不可见时保留最后可靠躯干基准，明确记录模式。
3. 如需要长期坐姿/仅上半身入画，设计“已标定上半身模式”并单独验证；不能继续依赖不可见髋部。
4. 基准不可观测而人又转身时记录失效，不能凭猜测带动双臂。
5. 重获基准平滑接回，不隐式改左右手腕零点。

身体与手部world landmarks原点不同，均为模型估计；不得直接拼接位置当作真实三维测量。向量旋转、ROI还原、左右符号和镜像须有已知答案检查。[MediaPipe身体坐标定义](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/python)

### 4.3 身份关联

保留已有一对一匹配，新增可靠预测和歧义判断：

- 图像距离先按宽高还原像素，再按手掌尺度归一化。
- 使用身体腕点、短时运动预测、历史身份；handedness作辅助。
- 最佳/次佳分配差距不足时标记歧义，不强行凑齐两只手。
- 每侧独立轨迹ID；新身份/重获需新来源证据，重复帧不确认。
- 关联权重用开发集确定，删除未经量纲验证的固定0.45/0.35加权。

状态机只影响相关模块。身份不确定时，不把夹爪命令发送给猜测的手臂。

`LOST` 是待测算法的内部状态，不等于验收样本的 `input_eligible=false`。输入是否满足可见度、照明、距离等前置条件，必须由独立保存的原始视频和盲审规则判定；输入合格但算法进入 `LOST` 的Episode仍计失败，不能事后排除。

## 5. 拇指—食指夹爪控制

### 5.1 第一阶段只做可靠开闭

检测器仍输出21点；只消费两个指尖不会自动降低推理成本。4/8号点决定夹爪开合，0/5/9/17等掌根点提供尺度、几何质量和腕姿态。[MediaPipe手部说明](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/python)

先实现“捏合闭爪、松开张爪”二值控制。验证通过后再增加连续开度。第一版不让两指尖轴驱动腕部，避免捏合退化直接扭腕。

### 5.2 特征和个人标定

候选特征：

~~~text
r3 = norm(h4 - h8) / palm_scale_3d
r2 = norm(pixel4 - pixel8) / palm_scale_2d
~~~

掌尺度由稳定掌骨距离稳健估计。侧掌投影分母接近零时禁止相除；估计三维尺度也要检查骨长、深度、遮挡和时间一致性。

左右各至少10次捏合/松开，覆盖正掌、斜掌及支持的转腕角度，记录闭合/张开/过渡分布。个人标定算法固定，左右参数独立。可用以下开发初值：

~~~text
a = 闭合样本比值P95
b = 张开样本比值P05
gap = b - a
T_close = a + 0.25 * gap
T_open  = a + 0.75 * gap
~~~

若gap≤0，或相对重复测量噪声过小，或某个必需角度不能区分开闭，则标定失败；必须改善输入/模型或补标定样本。固定0.35/0.60及gap>0.15不再作为通用保证。

二维/三维证据矛盾时输出未知。二维投影接近不能独自证明两指捏合；真实捏合的遮挡又不能永远拒绝，需要带标注的时序样本验证。无法区分时按第12节处理。

### 5.3 状态与时间确认

~~~text
可信且ratio < T_close -> CLOSE候选
可信且ratio > T_open  -> OPEN候选
位于迟滞区间         -> 保持既有状态
观测无效             -> UNKNOWN，保留开度但计观测不可用
~~~

候选至少两个不同来源观测，并满足确认持续时间。初始在30/50/70 ms中比较；缺失或观测间隔过长清空候选，不把遮挡前后的两帧直接拼成连续证据。

按漏检、误触发、真实响应时间共同选参数，不强制叠加三帧中值滤波。观测丢失不自动张爪，预测不产生新开合边沿。恢复后重新确认，保留原标定。

连续开度是后续独立验收项，二值通过不代表中间开度准确。若以后引入指尖轴，要区分有向手指向量和无向平行夹爪轴，不能随意翻转符号掩盖真实转动。

## 6. 手腕朝向与恢复

### 6.1 正交掌架与左右标定

从可靠掌骨构造正交右手基：

~~~text
z = normalize(h9 - h0)
x0 = h5 - h17
x = normalize(x0 - dot(x0,z)*z)
y = normalize(cross(z,x))
R = [x y z]
~~~

检查骨段长度、投影非退化、R.T@R≈I、det(R)≈1。左右掌心外法向符号和人体到机器人TCP的固定旋转通过已知姿态验证，不能把镜像反射当作旋转。

必须测试：掌心相对、掌背朝前、双掌向上/下、左右旋前/旋后。不能每次重置零点来掩盖错误的绝对朝向。

### 6.2 真实旋转门限按时间定义

保留当前旋转矩阵/旋转向量也可，不需要为了平滑强制换四元数。如果使用四元数，处理q/−q之后仍要检查真实创新量：

~~~text
dt = t_source_now - t_source_previous
innovation = rotation_angle(R_predicted.T @ R_observed)
limit = noise_allowance + omega_bound * dt
~~~

noise_allowance、omega_bound来自开发标定及需求速度。设置最大有效观测间隔；不能在长时间丢失后用巨大dt无限放宽门限。

单帧不可信只拒绝该观测；合理快速旋转应能被接受。重获除了连续方向还需掌面几何、影像支持、身份和可执行性；连续几帧同样错误的估计仍是错误。

### 6.3 缺失时保持相对前臂腕姿态

~~~text
R_relative_last = R_forearm_at_accept.T @ R_palm_at_accept
R_hold_now = R_forearm_now @ R_relative_last
~~~

保留该保持目标及IK连续性项，允许手臂抬起时手腕相对前臂不塌。不要设姿态权重为0后假定手腕保持，也不要同时锁死世界朝向与所有腕关节。

肘接近伸直时前臂基准也可退化，需维护轴连续性。持续失效应计入可用性和跟随误差，不能靠长期冻结通过验收。

### 6.4 完整腕部使用验证后的full模式

当前twist路径已有角度展开、>110°增量拒绝和部分重获处理；仅覆盖轴向旋转。完整腕部验收必须给full路径补齐质量筛选、保持与恢复，并验证屈伸/偏摆/旋转耦合。模式切换连续接入，不能直接跳到零位。

## 7. 手臂映射、IK与物理执行

1. 保留身体坐标内上臂/前臂方向，依据标定骨长和观测质量筛选深度异常。
2. 清点滤波位置并逐一消融；关键点、方向、腕向不是全部同时加重滤波。用真实dt更新。
3. 单位方向在方向空间连续更新，避免反向向量线性平均近零；不要独立平滑多个互相冲突的目标。
4. IK以上一解为初值，保留阻尼、关节限位与显式保持项；观察目标权重与保持约束分开。
5. 速度/加速度限制依据实际控制间隔；物理时间和墙钟时间分别记录，不用固定0.05 s掩盖控制超时。
6. 记录残差、奇异姿态、限幅、驱动力不足、避碰改道；目标正确但实际不动也算失败。
7. 保留物理碰撞与既有规划，绕行时实际跟随偏差仍计入；撞前停住不等于成功跟随。

手掌丢失不应冻结可靠肩肘；指尖丢失不应污染手腕方向。可独立更新的前提是对应侧身份仍可靠。

## 8. 实时预算和调度

必须区分曝光/采集、主机读取、识别、关联筛选、IK、控制排队、实际响应、显示。现有host_read_to_first_step_ms仅覆盖部分链路。没有可靠曝光时戳时写“读入后延迟”，完整响应另用同步参考录像测量。

优先保留现有同帧并行，使用人体适当低分辨率+高质量手部ROI、最新帧队列、按需全图恢复。异步模块必须保留来源时间，不能把不同时间的两条手臂直接拼成一帧。

Lite与Full同时比较质量、可用性和尾部延迟；不能假定更大模型一定更好。异步忙时可能忽略输入，应记录采集帧、处理帧、未处理帧，不能只对回调帧算成功率。[MediaPipe运行说明](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/python)

工程开发目标：识别/筛选P95尽量≤40 ms，读入至实际动作起始P95≤120 ms，为其他环节留余量。最终按第3节实际响应判定；各阶段P95之和不能直接当作端到端P95。

成员B原有20 Hz/50 ms交付指标单列验证；本方案的150 ms动作响应不能替代原50 ms指标。

## 9. 数据集和独立真值

### 9.1 数据划分

| 数据 | 用途 | 规则 |
|---|---|---|
| calibration | 个人尺度、腕向和捏合标定 | 标定算法固定，每次保存参数 |
| development | 调参、模型选择、消融 | 当前612帧录像属于此组 |
| regression | 已知失败长期复现 | 保留代表样本，相邻帧不是独立任务 |
| acceptance | 发布验收 | 新会话、新数据，版本与协议冻结后使用 |

按拍摄会话/日期拆分，不能把同一录像相邻片段分别放开发与验收。冻结基准、标签、失败证据、版本信息需保留；普通临时数据可按既有规则清理。本方案不执行删除。

### 9.2 真值不能来自被测模型

两名标注者依据原图标解剖左右、真实开合、遮挡和出画，标注时不看算法叠加结果。疑难样本裁决，并抽检其余样本。

单目原视频能审核二维及可见事件，不能独立提供完整三维深度和掌姿态真值。要验证第3节的三维角误差，需仅用于评测的同步标定第二视角、可靠标记/姿态参考等独立测量。参考方向误差建议小于容差的三分之一，事件时间不确定性≤33 ms。

没有可靠三维参考时，只能报告二维/捏合评测，完整三维跟随标记未验证。参考输入不能偷偷进入被测控制器；如进入，就成为新配置并重新验收。

### 9.3 最小记录字段

~~~text
episode_id, session_id, subject_id, split, input_hash
protocol_version, code_hash, model_hash, config_hash, calibration_id
input_eligible, eligibility_reason, adjudicator
frame_or_event_time, reference_side, reference_pose, reference_gripper
reference_valid, reference_uncertainty

~~~

无真值输出NOT_EVALUABLE，不能默认成功。正式批次缺参考必须补齐；补不齐就不能发布完整99%结论。

## 10. 正式验收与统计判定

### 10.1 分母与失败规则

~~~text
完整成功率 = 满足所有条件的Episode / 预先定义范围内全部Episode
全部尝试成功率 = 成功Episode / 全部开始的尝试
~~~

同时报告两者、输入无效率、不可用时长、方向误差、事件漏检、额外触发及延迟。算法LOST/暂停不能证明输入无效。清楚入画却识别失败、结果过期、异常退出必须留在分母。

短时保持也要通过实际误差和时延条件。“99%”是目标分布中的概率，不表示任意一组100次都最多失败一次。

### 10.2 一次固定样本的正式验收

默认预注册：固定版本与输入分布，400个新的独立完整Episode；全部采集后统一判断。有效动作共100分钟，另计准备和标注。正常/斜掌、交叉、短遮挡、位置和速度按冻结分布抽取，逐类另报结果；总体99%不能自动推出每类99%。

跨多天多会话采集；同一录像重复400遍不等于400独立试验。若试验受会话、同次校准强相关支配，应按独立会话设计或采用分组统计并增加数据，不能直接套用二项置信界。

在独立同分布伯努利试验假设下，以单侧95% Clopper–Pearson精确下界为准：

~~~python
from scipy.stats import beta

def lower_success_bound(successes, trials, alpha=0.05):
    if not (0 <= successes <= trials and trials > 0 and 0 < alpha < 1):
        raise ValueError("invalid counts or alpha")
    if successes == 0:
        return 0.0
    return float(beta.ppf(alpha, successes, trials - successes + 1))

lower = lower_success_bound(400, 400)
statistical_pass = lower >= 0.99
# 统计通过还必须满足预注册协议、参考质量和复合成功条件。
~~~

| 固定样本结果 | 单侧95%下界 | 是否支持该范围内≥99% |
|---|---:|---|
| 400/400 | 99.2539% | 是，前提是试验及复合判定有效 |
| 399/400 | 98.8196% | 否 |
| 990/1000 | 98.3097% | 否 |
| 996/1000 | 99.0870% | 是，但须事先采用1000次方案 |

方法依据：[SciPy精确二项置信区间](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats._result_classes.BinomTestResult.proportion_ci.html)。表内为本次本机计算。置信下界不是所有未来动作的确定保证。

不得400次失败后临时加样到1000次直到通过。默认预注册一次正式确认；若计划多轮正式声明，必须在第一轮开始前预注册轮数或显著性分配，例如从 `r=1` 起使用 `alpha_r=0.05/2**r`，并按每轮实际alpha重新计算样本量。不能先用完整 `alpha=0.05` 失败后再追加检验预算，也不能每轮都用5%且只展示成功的一轮。

### 10.3 夹爪事件与误触发

开发集至少标1000个开/合边沿，左右/开合/角度组分别报告。它们用于定位问题；同一Episode中的相关事件不能当作1000个独立完整任务。

漏一个边沿、重复一个或额外开合都会使该Episode失败。不能用大量保持张开的帧稀释闭合识别错误。

额外触发按“次数/无开合意图的观察分钟”报告。旧版0.1%缺少分母已取消。如果以后独立声明负例窗口误触发概率≤0.1%，需要另一个预定义实验；单侧95%上界需至少2995个独立窗口零误触发。

### 10.4 开发余量与失败预算

开发方向应朝99.9%复合成功率优化，为发布留余量；少量开发样本不能证明这个概率。真实成功率恰为99%时，400次全过概率仅约1.8%。

| 失败来源 | 每个完整Episode的最大预算 |
|---|---:|
| 图像/检测不可用 | 0.20% |
| 手臂方向与映射 | 0.20% |
| 手腕方向 | 0.20% |
| 左右身份 | 0.10% |
| 夹爪事件 | 0.10% |
| IK/执行/延迟/其他 | 0.20% |
| 合计 | 1.00% |

预算用于开发排序，不是实测。各故障可相关，不能假定独立相乘。每次失败保留全部原因与首发原因，修最高贡献项并重跑全部回归。验收失败后本批转回归，新版本使用新独立数据并遵守正式检查次数规则。

## 12. 软件仍未达标时如何继续

P5至少完成两轮独立开发会话后，依据失败证据选择：

| 主要剩余问题 | 改进方向 | 必须重新验证 |
|---|---|---|
| 手太小、模糊、曝光拖影 | 调整机位、照明、曝光和有效手部像素 | 原要求动作范围是否完整，采集延迟 |
| 可见动作重复估错 | 真实标签下比较模型/时序估计，必要时训练并留会话外验证集 | 泛化、左右子组、尾部延迟；伪标签不是真值 |
| 侧掌/交叉/前后方向无法区分 | 评估第二个同步真人视角，或经标定深度/姿态输入 | 外参、同步、遮挡、融合冲突和整套验收 |
| 目标正确而腕部塌落或执行慢 | 查IK参考、奇异姿态、驱动误差、限速及物理负载 | 执行回归，不能把所有失败都归于识别 |
| 新输入不在现有项目范围内 | 保留单目已测结果并明确未达99%，另评估扩展 | 范围变化需先与需求一致并重新冻结 |

新增视角或深度不自动保证99%，它解决部分信息不足，仍需试验。先做低成本单目改进；只有证据表明信息不足时再评估扩展，机器人始终可保持纯仿真。

## 13. 最终交付与结论模板

完成应包含：统一接口/坐标规范；个人标定配置与哈希；捏合及腕部恢复代码；回归测试；同步原始视频和参考标签；目标/实际轨迹；时延和失败日志；开发对比；独立验收报告。

正式通过后才使用下列模板：

> 在[用户、相机、动作范围]与[版本/标定协议]下，按照预注册15秒双臂协议完成N次独立验收，S次满足全部跟随、腕向、夹爪和响应条件。样本成功率S/N；本轮预注册 `alpha=[实际值]`，相应单侧 `[1-alpha]` 精确下界为L。输入无效尝试M次，另列原因。结论适用于该输入分布，不代表任意遮挡、任意用户或自主抓取任务。

未完成三维参考、实时执行或独立验收时，该部分写“未验证”。只有复合条件和统计要求同时满足，才写“达到本方案99%发布要求”。
