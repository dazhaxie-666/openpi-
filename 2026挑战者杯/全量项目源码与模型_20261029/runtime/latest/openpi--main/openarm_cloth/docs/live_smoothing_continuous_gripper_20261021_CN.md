## 原因和修改

原记录 1026 帧，A 名义参考相邻帧最大分量有接近 30° 的跳变。
旧执行端限制了每帧角位移，却在每个控制周期直接切换恒定速度前馈；
新回归测试测得帧边界前馈加速度突变达 8800 rad/s²。
识别丢失时把目标直接替换成滞后的编码器位置，也会产生目标跳变。

- `live_reference_conditioning.py`：按真实源时间间隔进行速度自适应低通，重复源帧不重复更新。
  在物理时钟上生成连续速度、限制加速度的关节参考；静止时抑制细碎变化，运动时提高响应。
  调参参考 [1€ Filter 作者说明](https://gery.casiez.net/1euro/)，此处使用指数离散化的自适应低通，
  不改写 A 已有的人体滤波。新增执行平滑确实会带来延迟，不能称零延迟。
- 动作模式角速度上限仍为前四轴 2.5、后三轴 4.4 rad/s；新增加速度上限 14 / 24 rad/s²。
  丢失或暂停时从当前参考平滑减速，不突然跳回编码器；恢复时跟随最新参考，不排队补动作。
- `pose2arm_task_mapping.py`：每只手独立计算拇指尖—食指尖距离 / 掌宽，连续映射到
  B 每个滑动指节的 0–0.044 m。比例 .15 与 1.2 是连续插值的闭合/张开端点，
  中间所有距离均有中间开度，已经取消“两个阈值决定全开或全闭”的默认 A 夹爪控制。
  手指信号也做自适应平滑；手部缺失保持最后开度，不自动张开。动作模式还限制夹爪速度和加速度。
- `run_human_task.py`：删除右夹爪被任务 `holding` 状态强制覆盖成 0/.044 的逻辑，
  暂停/缺失保持当前连续开度。旧手势阈值只负责启动和意图事件，不改写 A 开度。
- 桌面任务复用相同关节平滑器，沿用较低速度上限和原 B 接触检查；
  受阻侧重置累积运动状态，另一侧和夹爪仍分别处理。B 自主抓取控制器增益未变。
- 动作预览新增左右夹爪开度百分比。记录增加平滑后目标、执行速度、捏合比例和米制开度，
  便于继续定位识别噪声与实际执行误差。

旧 `--mapping b-legacy`、`--mapping wrist` 和辅助抓取的手势逻辑保留各自历史用途；
本轮默认连续夹爪覆盖 `live` 和 `human-task --mapping pose2arm`。
