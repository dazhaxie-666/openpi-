# 搬运未张手却下沉、停止的修复

现场来源：`outputs/shared_grasp/20261027_134400_893090/`。旧记录和失败复现完整保留。

## 现场发生了什么

第一试次 149.249 秒进入搬运，150.176 秒发生一次位置/姿态求解拒绝，随后进入持物暂停。
150–153 秒，夹爪目标始终为闭合的 0 m，但机械臂 TCP 从约 0.515 m 降到 0.439 m，
物体跟随下沉。157.061 秒才出现后续的张手下降请求。因此，最初的下沉发生在松爪指令之前。
第二试次同样在搬运位姿受限后进入持物暂停。

这不是缺少闭合输出，也不能把最初的下沉归因于用户提前张手。

## 修复

1. 共享模式持物 HOLD 保留最后通过检查的电机目标，避免每帧以受重力影响的编码器位置重设目标。
   新搬运命令被拒绝时也恢复之前的安全目标；夹持压力保持。
2. 搬运中单次位置不可达或碰撞拒绝只拒绝该增量并重定中心，保留搬运阶段。
   用户移回可达方向即可继续，不会因单次动作受限永久停在持物暂停。
3. 精确抓取姿态在搬运边界不可达时，允许共享搬运专用的有限姿态求解：
   相对固定抓取姿态最多 8 度，位置误差最多 4 mm；仍通过 B 的关节限位及完整持物路径碰撞检查。
   这个回退不用于抓取对准、抬升或支撑放下，也不允许姿态逐帧无限漂移。
4. 夹持反馈持续异常仍会保持并等待明确放下；界面区分“夹持反馈异常”与“手腕缺失”。

张手操作、近处接管、人工靠近与搬运、完整任务分段保持上一版流程。
没有修改人手识别、掌部深度映射、B 电机参数、物理质量、摩擦、关节限位或时间步。
