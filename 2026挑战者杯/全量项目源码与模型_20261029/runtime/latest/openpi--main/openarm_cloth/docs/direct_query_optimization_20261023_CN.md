# 直接手腕遥操执行查询优化及65秒复测

最近真人记录进入 DIRECT 后，整循环中位约85 ms，执行环节约41 ms，物理推进约16 ms，实际刷新界面时约25 ms。默认20 Hz是目标频率，并不是该记录已经达到的频率。

## 实现

直接手腕及独立夹爪命令使用轻量查询：

- IK的试探残差仅更新机器人/夹爪几何变换，不再每次计算接触力与加速度。原求解器新增默认关闭的 `kinematics_only` 参数，仅直接遥操显式启用；B原有辅助抓取求解默认行为保留。
- 位置优先回退同样使用几何更新，原8 mm位置误差、20度腕部变化限制及执行限速保留。
- 复用独立的 IK 查询状态，每次从当前编码器和相机估计对象位姿重新填充。不会复用旧目标，也不会把仿真对象真值送入规划。
- 直接命令的碰撞查询使用完整位置/碰撞/约束构建流水线，不计算查询不需要的力和加速度。夹持物体时先更新机械臂几何，再用相机来源的夹持几何更新对象。分段采样数量、穿透阈值、已有接触逃离条件均保留。
- 辅助模式和原始A关节参考路径保留原查询方式。B实际物理推进、模型、增益、力矩限制和步长不变。

每行增加 `planning_query_ms`、`ik_ms`、`collision_check_ms`、`payload_ms`，诊断汇总也包含这些耗时。执行总耗时仍单独记录，不能把子项分位数相加当作总分位数。

## 对照与回归

在同一台电脑，以29组记录编码器姿态构造1 mm运动目标，隔离执行查询对照：中位耗时约38.9→14.8 ms，95分位约42.9→16.6 ms；关节目标最大差为0，拒绝/告警判定一致。该测试不包含实时相机、后台推理、GUI和物理推进，不能据此宣称整个系统达到20 Hz。

新增查询回归覆盖：碰撞深度与完整求解一致、包含穿透与夹持对象的配置、查询状态复用时刷新编码器且只取相机对象位姿、IK结果及状态恢复等价。复测提示也有分段测试。原有抓取、接触恢复与动态执行测试仍需通过。

完整回归B401项，398通过、3跳过；A接口11项全部通过。最终源码的35项针对性回归及21行显式模拟输入集成通过，验证自动到时保存、细分耗时与response协议；不作为真人视频或任务成功。

## 已准备的复测

```powershell
Set-Location -LiteralPath 'D:\openpi\latest\openpi--main'
& .\run.ps1 -Mode human-task -ScriptArgs '--mapping','wrist','--gripper-mode','continuous','--diagnostic-recording','--diagnostic-protocol','response','--preview-hz','10'
```

该模式后台队列保存人体视频，关闭逐帧机器人PNG保存，保留机器人的场景观测。队列满或写入错误会报告，不把不完整录像当成功记录。相机与MuJoCo预览仍最多10 Hz，键盘每个控制周期处理。个人标定、增益与开度映射保持现有配置。

确认 READY、右手放舒适中心后，按空格/START。屏幕提示从开始后计65秒，暂停时不计时，Q可提前保存。

| 时间 | 动作 |
|---|---|
| 0–5秒 | 手腕居中，手指半开，保持静止 |
| 5–15秒 | 保持半开，手腕慢慢左右移动 |
| 15–25秒 | 保持半开，慢慢上下移动 |
| 25–35秒 | 保持半开，慢慢伸手、缩手 |
| 35–50秒 | 手腕不动，接触→小缝→半开→全开，再缓慢合回；各档保持约2秒 |
| 50–55秒 | 用另一只手短暂遮挡手指约1秒，随后恢复半开并完整入镜 |
| 55–65秒 | 保持半开静止，观察是否平稳恢复，等待自动保存 |

复测只观察人体跟随、开度保持与识别恢复，不要求这次抓取。后续按视频源时钟对齐目标/实际TCP与夹爪状态，检查工作区裁剪、有效输入保持段、执行查询与总循环耗时。个人录像、关键点、标定和本地基准全部保持本地。
