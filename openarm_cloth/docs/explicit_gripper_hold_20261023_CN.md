# 显式保持夹爪开度：先保证移动操作可靠

## 问题边界

真人确认保持半开移动手腕时，视觉开度指令仍漂移。记录对照显示源切换只解释少量跳变，固定骨长或掌面投影没有明显改善。试验性的个人模板模型虽然能让半开片段变平稳，却会将另一段录像中的部分真实闭合预测为半开，未通过保留真实开合响应的验收，因此没有接入生产，也没有改写个人标定。

本次新增的是操作者显式控制的开度保持功能，不是宣称单目视觉漂移已被根治。默认仍为原来的连续捏合控制；没有依据手腕速度、动作阶段或时间自动锁定，也没有将录像阶段标签作为运行控制输入。

同时修复一个连续跟踪中的停顿原因：已经TRACKING时，开度跨过closed/middle/open诊断类别不再重新进入REACQUIRING。连续值仍逐帧滤波更新；检测丢失、冲突、时序断开后仍需重新确认。开关模式原有类别确认保留。这项修改减少额外等待，不代表原始几何漂移已经消失。

## 使用

仅适用于 `human-task --control direct --mapping wrist`：

- 空格/START开始后，按 **H**：指定50%开度并保持。移动手腕时继续驱动机械臂，视觉捏合值不改变夹爪参考。
- 连续控制中按 **L**：保持机器人当前的开度目标；不是抓取确认，也不移动机械臂目标。
- 已保持时再按 **L**：恢复连续手指控制。需要解除时刻之后两帧新的、不同源序号的有效手部观测；重复旧帧、丢失或暂停不会完成确认。
- 暂停、未开始、结束或只有保持命令时，不注入新的夹爪运动。接入B时仍保留原夹爪速率限制与碰撞检查；H并不瞬移关节。

窗口左下主标题与右侧状态显示 `GRIPPER LOCKED` / `GRIPPER RECONNECTING`，不让保持状态混同于视觉准确识别。G/O标定与原有C/R/M、空格、Q控制保留。原始A双臂映射和辅助抓取不启用这些键。

```powershell
Set-Location -LiteralPath 'D:\openpi\latest\openpi--main'
& .\run.ps1 -Mode human-task -ScriptArgs '--mapping','wrist','--gripper-mode','continuous','--diagnostic-recording','--diagnostic-protocol','response'
```

复测：确认READY，空格开始，按H后左右/上下/前后移动；到35秒的开度分档提示时按一次L，再做接触、小缝、半开、全开。检查显式保持时目标恒定，解除后能响应真实开合。Q可提前保存。仅凭保持模式稳定不能认定视觉漂移已解决。

记录增加 `gripper_input_mode`（continuous/locked/reconnecting）、`gripper_locked_reference_m` 及人工按键事件。`pinch_reference_m` 仍记录视觉输出，`action_target` 记录经过保持选择和B限制后的实际参考，分析时应分开。源码可共享；个人标定、视频、训练试验与诊断输出不上传。

## 验证

测试覆盖：视觉开度任意波动时保持目标不变而机械臂目标保留；默认不自动锁定；恢复需要两帧新有效源；无效输入中断恢复确认；暂停/未开始/结束/丢失不注入新动作；非法开度拒绝；B动态执行器达到半开时机械臂仍能运动。不会将个人模型的训练回放结果作为新真人验收。

完整回归B409项，406通过、3跳过；A接口11项全部通过。最后的连续跨档修复另以54项针对性回归验证，全部通过，其中包含新增的跨档保持TRACKING及丢失后仍需重新确认的用例。

对同一真人记录的特征/时钟回放精确复现原视觉开度参考。连续跨档修复使DIRECT期间PINCH_CONFIRMING行数由101降为8，有效参考行占比约80.5%升至89.3%。这是减少额外确认等待的回放结果，不是识别准确率提升或开度漂移已经根治。21行显式模拟输入集成也验证了默认连续模式、新增记录字段及到时保存流程。
