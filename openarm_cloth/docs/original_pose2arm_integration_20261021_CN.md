## 已接回的链路

`BimanualHumanStream.pose_raw` → **A 的 `openarm_live.OpenArmLiveController`**，左右臂各一实例 →
A 原根部/肢体 One Euro 平滑 → `Retargeter.calibrate`（10 个不同的有效观测，臂长中位数）→
`frame_to_pose_target`（肩、肘、腕方向/位置/臂平面）→ `OpenArmIK.solve_pose_likeness` →
A 原 7 关节参考 → B 原执行器。

接入前检查 A/B 两侧标准关节点运动学一致性，最大误差约 **1.62 微米**。
不把 A 与 B 两套关节角相加；也不再用第二套固定腕姿笛卡尔 IK 覆盖 A 的关节参考。
A 只提供参考，B 继续执行实际动力学；夹爪用 B 的米制滑动关节，捏合/张手意图独立处理。
这里是 A 原在线肩肘腕映射，不是新增的手掌三轴姿态测量模型。

观察质量门控保留：左右肩、对应肘/腕有足够置信度，身体框架点有限，源数据未过期。
缺失侧保持，另一侧独立继续；不会把 A 对缺失输入的旧缓存伪称为新检测。
A 只读取未平滑的同帧人体世界关键点，再做自己的原始平滑，避免两次过滤增加迟滞。

实时相机识别、A 求解、B 控制/界面彼此分开。A 工作线程只保留一个正在求解的帧和一个
可替换的最新待处理槽，不保存旧动作队列；C 重标定时丢弃旧代结果。视频/软件检查走
同一映射类的确定性同步入口，不能据此声称摄像头端到端时延。

## 先验证 A 原始双臂动作

```powershell
Set-Location -LiteralPath 'D:\openpi\latest\openpi--main'

```

现在 `live` 默认 `--mapping pose2arm`，使用 B 派生的机器人动作场景。
没有桌面、方块、抓取任务的视觉门控或任务规划器覆盖动作；仍由 B 物理执行器驱动，
不是逐帧写 qpos 的运动学演示。原碰撞网格、摩擦、执行器力矩限幅及增益保留。
复用已有动作模式连续插值/速度前馈控制，不修改自主抓取控制器。

左右肩、肘、腕留在镜头内，先自然举臂并保持可见，界面分别显示左右标定进度。
每侧收齐 10 个不同的有效帧后独立开始跟随。**左手→左臂、右手→右臂**，镜像不换身份。
捏合闭爪，张开拇指/食指松爪；C 重新人体标定，空格暂停/恢复，M 切换镜像，Q 保存退出。
暂停恢复后是绝对的整臂姿态跟随，不是旧手腕模式的相对起点重定位。

录像/数值记录仅本地保存至 `outputs/a_live/<时间>/`；加 `--no-save-video` 可只保存数值。
新目录避免与旧 `outputs/live_bimanual` 数据及历史验收混用；包含 MJB 模型、A 源码哈希、
标定比例、A 名义关节参考/原观测和 B 实际动作、数值记录质量报告。

## 在抓取场景使用同一条 A 链路

```powershell
& .\run.ps1 -Mode human-task -ScriptArgs '--mapping','pose2arm','--arms','both'
```

这已是直接模式默认值。先完成标定，右手张开并按空格/点击 START 开始记录任务控制。
左右臂均跟随对应人体整臂，捏合/张手分别控制夹爪。抓取、抬升、搬运、放置仍由人完成，
不自动切到视觉抓取轨迹；右臂红方块任务的独立评分保留，**不宣称双臂抓取验收完成**。
`--arms right` 可只控制右臂。

桌面和物块在该模式真实存在，因此 B 会对 A 请求限速并采样检查接触：
受阻侧局部缩小步长或保持，另一侧仍独立尝试；夹爪开合单独检查，不因手臂受阻而一并丢弃。
没有绕障自动路线，也没有放宽原碰撞门限。因真实障碍保持仍可能发生，不能承诺任意动作永不卡。
抓空、掉落可继续调整；仅操作结束后统计结果。外部查看器复位会使场景时钟归零，
该条记录停止并提示重新启动，避免沿用失效工作位。

新记录保留当前人体与 A 所消费人体的不同源序号/时间戳，避免异步来源混淆；
`a_reference_joint` 是 A 原名义参考，`action_target` 是经 B 限速/接触检查后的实际目标，
`a_reference_valid`、`a_calibration_scale`、`a_blocked_sides`、`a_applied_step_fraction`
和 `control_work_ms` 说明保持原因及实际执行比例。
