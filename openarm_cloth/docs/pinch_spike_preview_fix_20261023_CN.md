# 连续捏合去毛刺与 Windows 预览等待修正（2026-10-23）

本次只调整 `human-task --mapping wrist --gripper-mode continuous` 的手指参考处理，以及 human-task 的预览输入轮询。原有个人标定继续使用。完整 A 肩—肘—腕映射、B 物理步长、执行器增益、力矩限制和碰撞检查保持原配置。

## 改了什么

1. 接近闭合的参考（归一化开度低于15%）需要至少3个新来源观测，且首末间隔至少120毫秒。确认期间保持最后开度；丢失、冲突、来源断流会清除确认。画面显示 `PINCH_CLOSURE_CONFIRMING`。这是闭合证据确认，不是15%的开度下限；持续真实捏合仍能到0%。
2. 已接受的连续开度增加因果三帧中值去毛刺，再经过原来的低通滤波。重复读取同一帧不会推进窗口。持续变化通常增加约一个来源帧的滤波延迟；接近闭合还需上述确认。手腕位置控制不经过此窗口。
3. HighGUI 使用 `cv2.pollKey()` 处理每个控制周期的键盘及关窗事件，避免 Windows 上 `waitKey(1)` 等待一个系统时钟周期。

连续开度仍由观测决定，正常运行不需要 H/L。H/L 保留为操作员主动保持的辅助键，没有按手腕速度或诊断阶段自动锁定。

## 已验证的改善

用最近65秒录像的相同 r2/r3 输入和来源时间戳离线回放，旧版参考复现误差为0：

- +10.32秒翻手异常，原开度参考3.46%，修正后保持28.72%。左右移动段低于5%开度的参考从1行降为0行。
- 以新来源观测的相邻参考变化绝对值均值衡量毛刺：左右移动2.60→1.51个百分点（约降低42%），上下移动2.10→1.15个百分点（约降低45%）。这是参考变化指标，不是独立的手势识别准确率或人体真实开度误差。
- 另一段用户确认保持半开的录像，相同版本基线对比下，左右/上下指标分别2.32→1.46、2.33→1.31个百分点。其前后段95百分位变化反而7.86→9.59个百分点；中值窗口不能保证所有恢复跳变都减小。
- 本机60次输入轮询小测试：`waitKey(1)` 中位15.43ms，`pollKey()`小于0.01ms。该测试不包含人体识别、渲染和仿真，不能据此宣称实时帧率已经达到20Hz。
- 全量 B 检查421项，418通过、3跳过；A检查11项通过。最后新增的物理夹爪回归另随11项手指检查通过：半开保持经过短暂异常，之后持续捏合能驱动B真实模拟执行器闭合。

## 尚未解决的限制

单目模型对手背、遮挡的持续深度偏差仍存在。短时保护和中值滤波不会把错误的稳定估计变成真实开度；不能宣称“保持半开移动时始终50%”。同一录像40–48秒的部分真实接触仍可能被3D高估，输出约15–25%开度。曾尝试用二维指尖重合覆盖三维估计，但在另一段已确认半开录像上增加误闭合，因此未部署该方案。

本次没有更换识别模型、训练个人模型或重写标定。私人录像、关键点、个人标定和逐帧分析均留在本地 outputs，不上传仓库。

## 复测

无需重新标定，重新启动程序才会载入新代码：

```powershell
Set-Location -LiteralPath 'D:\openpi\latest\openpi--main'
.\run.ps1 -Mode human-task -ScriptArgs '--mapping','wrist','--gripper-mode','continuous','--diagnostic-recording','--diagnostic-protocol','response'
```

点击摄像头预览窗口，SPACE开始，按照提示完成65秒。保持半开进行左右、上下、前后移动；35秒后按提示依次捏合、小间隙、半开、全开，每种保持约2秒。此次不要按H/L，以便验证连续控制。程序自动保存，Q可提前保存退出。

复测重点：翻手是否还突然夹死；保持半开时是否仍明显漂移；有意捏合能否闭合、有意张开能否恢复；相机预览和机械臂跟随是否更流畅。诊断阶段名只是操作提示，不能代替实际录像里的动作真值。
