# 单臂实时遥操修复版（2026-10-26）

## 直接使用

```powershell
& 'D:\openpi\启动修复版遥操.ps1'
```

也可在主项目运行 `& .\run.ps1 -Mode single-arm`。
保持常用中立姿势，SPACE 开始；约半秒内自动采集新鲜肩宽和掌形参考。
C 重新定中心，SPACE 暂停/继续，Q 保存退出。已有个人捏合标定保留。
日常没有强制的分轴检测或 50 秒流程；正常入口仍默认不保存人体视频。

## 修复了什么

本轮按用户提供的《实时遥操故障排查与修复指南》分层核对，并保存局部可回退副本。
原 MediaPipe Tasks full 身体/手部模型、RGB 输入、720p 分辨率及置信度未改。
默认关闭额外 RTMPose 肘点显示模型，避免把另一套显示估计混成原骨架。
异步最新图像与轻量三维刷新保留，模型不在逐帧循环中反复创建。

原算法固定模板，却把当前模型估计的三维掌向直接用于投影；当前掌向不准时，
会被掌形或重投影门控持续锁住。新 `palm-planar` 分支用初次五个有效掌形建立固定近似平面，
通过 OpenCV IPPE 和 LM 从本帧二维掌点同时拟合朝向、平移；后续不再依赖每帧的三维掌向。
旧 `palm-relative` 分支原样保留作为对照。

左右/上下新 `fixed-image` 分支用图像手腕相对双肩中点的位移和固定五帧肩宽尺度。
之后不逐帧改变尺度，也不让身体模型的 Z 或估计肩轴转动混入左右方向。
它是固定、正面相机下的名义控制单位，不是人体真实公制测量。
原始身体点、实际位置输入、映射目标、IK 和实际 TCP 分开记录。

修复同时保留：过期/缺失观测保持、平面近侧视不可观测保持、重投影质量检查、
大跳变两次新鲜观测确认、B 的限速、工作区、IK/碰撞与腕姿约束。
C 的重新定中心会等待新标定完成后生效，避免标定期间丢掉一次按键或恢复时跳动。
没有放宽 B 的执行器参数，也未连接实体机械臂通信。

## 现场数据复现与单变量对照

最近真人记录 `outputs/human_task/20261026_164012_231649` 活动段约 99.6 秒，
实际控制约 19.06 Hz。1551 次新鲜来源中，旧前后输入只有 727 次有效；
约第 85–95 秒前后输入连续不更新。

用这次保存的同一组人体/手部观测重跑旧算法，X 输出最大差异为 **0**，
各保持原因计数也完全一致，确认复现的就是现场故障。

| 修改 | 前后有效 / 新鲜来源 |
|---|---:|
| 旧算法复现 | 727 / 1551 |
| 只改平面前后求解 | 982 / 1551 |
| 只改固定图像位置 | 717 / 1551 |
| 两个独立修改合并 | 964 / 1551 |

合并版本在原第 85–90 秒恢复 12 次、90–95 秒恢复 25 次前后更新。
这只是同特征下的可求解数量，**不是深度准确率**，也不能声称所有握姿全程无冻结。
手部缺失、侧掌不可观测和身体置信度不足仍可能保持；没有人体真实深度真值。
“只改位置”没有提高前后有效数，故没有把它冒称为深度修复。

## 回退与采用来源

本轮接线前源文件快照位于 `outputs/emergency_repair_20261026/before_integration/`。
没有覆盖旧环境、重置 Git 或删除失败记录。
需对照之前配置时运行：

```powershell
& 'D:\openpi\启动修复版遥操.ps1' -PreviousMapping
```

该开关恢复上一轮上身模型位置和旧掌部前后求解，保留同一 B 环境，不冒称“已找到周五最佳版本”。

本轮实际使用 OpenCV 的 IPPE（Collins、Bartoli 的 *Infinitesimal Plane-Based Pose Estimation*）
及 LM 精化，接口和算法出处见
[OpenCV 官方 PnP 文档](https://docs.opencv.org/4.x/d5/d1f/calib3d_solvePnP.html)。
延续此前 OAT 掌点投影的相对控制思路；不是 OAT 完整复现。
没有接入 ESFP 的 ROMP/HPSTM，没有增加模型训练或新大型模型。
