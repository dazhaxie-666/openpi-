
大字状态显示 `ARM TRACKING`、`ARM HOLD` 或 `PAUSED`，手指检出与手臂跟随分别显示。

## 已修复

1. 撤销上一轮 5 Hz 的日常摄像头预览设置。OpenCV 窗口在独立线程读取最新原始帧，
   刷新目标 30 Hz；显示既不等待姿态推理，也不进入机器人输入通道。
   帧和状态均只保留最新一份，不排队播放旧图。键盘、鼠标事件由 GUI 线程回传控制循环。
2. 状态面板按状态更新频率缓存，摄像头图像只在新缓冲区到来时缩放；
   Windows 的 1 ms 计时请求与原 B live 入口一致，退出时恢复。
3. 三维预览与摄像头使用独立刷新频率；修复定时器按上次延迟完成时间重新排期、
   导致轻微控制抖动时隔帧刷新的问题。错过的显示时隙直接丢弃，不补播。
4. 直接控制的小幅位移采用连续死区：原先积累超过 2 mm 后一次追上，
   现在只跟进噪声容差之外的新增位移。没有叠加时间平滑窗口；
   配置的速度、目标超前量、边界防积累、IK/碰撞检查及 B 增益保持原有约束。
   辅助抓取继续使用原逻辑。

## 如需定位“骨架正常但 ARM HOLD”

可显式启用本地诊断录像，以便将实际图像与同一来源序号的姿态、门控和执行目标对齐：

```powershell
& .\run.ps1 -Mode single-arm -ScriptArgs '--diagnostic-recording','--diagnostic-protocol','response'
```

START 后按提示进行分轴移动、开合与短暂遮挡，65 秒自动保存；Q 可提前结束。
这是新的诊断输入，不作为独立成功率。人体视频和标定只保存在本机。
