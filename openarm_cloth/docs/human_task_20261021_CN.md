# 真人意图驱动的单臂抓取与放置

新增日期：2026-10-21。主目录：`D:\openpi\latest\openpi--main`。

这次新增的是独立 `human-task` 模式。人决定接近、抓取意图、搬运方向和释放意图；
B 的 RGB-D、IK、轨迹检查和原执行器负责精对齐及执行。
自由动作 `live` / `fusion` / `fusion-replay`、自主抓取 `grasp` / `tabletop` 不改用途。

## 现在已经实现什么

流程：准备 → 人手相对位移接近 → 人捏合触发 → 视觉规划 → 过渡位 → 接近位 →
下降 → 闭爪确认 → 辅助抬升 → 人手相对位移搬运 → 目标区张手请求 → 辅助下降 →
松爪 → 撤离 → 相机确认，并由独立物理评估决定最终 PASS。

- 首版固定右臂、已知尺寸红方块；非工作臂维持 B 的待机目标。
- 用拇指/食指尖距离除以手掌宽度识别捏合，默认闭合阈值 0.35、张开阈值 0.8。
  连续新观测保持 0.15 秒才确认；同一帧重复使用不能算多次确认。
- 远处捏合不启动自主抓取；保持捏合并进入 10 cm 邻域后才允许视觉辅助。
- 接近和搬运用躯干相对手腕位移，默认增益 0.7；保持腕姿，避免自由转腕影响夹持。
- 2 mm 目标死区、末端目标限速 0.12 m/s、目标相对实际末端最多超前 4 cm。
- 自动阶段采用平滑起止轨迹；B 的 PD 增益、力矩限制、相机标定和冻结 XML 不改。
- 丢失手腕保持；手指暂时不可见但手腕有效时仍能进行位置跟随，不能产生抓取/释放意图；
  自动对齐/闭爪等辅助阶段遇手指缺失则保持。持物期间维持闭爪；重新识别、暂停恢复或 C 重定位后从实际末端
  重新建立相对运动起点，不突然追赶旧的人手位置。连续丢失手腕或辅助阶段连续丢失手指 2 秒结束并记录失败。
- 只有在绿色目标区上方张手才进入放置；先辅助下降到支撑高度，再松爪。
  不会在远处因张手而直接把物体扔掉。
- 抓前复查目标位移；持物查询同时包含推算的方块体积与姿态。使用采样碰撞检查，
  不宣称连续路径安全或实体硬件安全。
- 放置高度根据估计持物姿态、夹持偏移与最低角点计算，避免方块倾斜时角点先穿入桌面；
  这项修正不移动人选择的放置 XY，也不放宽碰撞阈值。

## 第一次真人测试

准备普通 USB 摄像头，正面拍到肩、躯干和右手。操作者看仿真窗口反馈来移动手。
这次不需要在现实里放一个与仿真完全对应的方块。

```powershell
Set-Location -LiteralPath 'D:\openpi\latest\openpi--main'
# 初次熟悉操作放宽到 60 秒；正式 15 秒任务去掉 --timeout 60
& .\run.ps1 -Mode human-task -ScriptArgs '--camera','0','--timeout','60'
```

1. 展开拇指与食指，按空格或点击画面下方 START。提前按也会保留请求，待输入有效且
   张开手势稳定 0.2 秒后进入 FOLLOW；画面会显示具体等待原因。
2. 右手移动，使仿真夹爪接近红方块。C 可重新建立手部/末端的对应起点。
3. 靠近后捏合拇指与食指并保持，系统对齐、闭爪并抬升。
4. 看到 `TRANSPORT` 后再移动手，把方块运到绿色目标区上方。
5. 张开拇指与食指；系统辅助下降、释放、撤离并判定结果。

摄像头预览默认镜像，M 可随时切换，启动时加 `--no-mirror-preview` 可关闭。
只翻转预览，不翻转识别输入、左右手身份、原始人体视频或仿真相机图像。
空格或点击按钮暂停/恢复；Q 或关闭窗口取消。首版一条进程录制一条任务，下一条重新运行命令。
复位时机械臂采用预设工作区位姿，这只是仿真初始条件；任务开始后的动作由动力学
执行器产生。初始方块为 `.43, 0, 30°` 的测试布置，不会把该参数传给识别器或控制器。
`--cube-test-pose X Y YAW_DEG` 可另设测试布置。目标区来自 B 已有配置 `.43,-.10`，半径 3 cm。

默认本地保存人体关键点、仿真 RGB 和数值记录；原始人体视频只有加
`--save-human-video` 才保存，不上传。摄像头编号不对时改为 `--camera 1`。

## 离线视频与自动测试的区别

离线视频必须包含真实的接近、捏合、保持、搬运和张开，而不能把任意摆臂视频当作
抓取示范。视频不提供对仿真的即时视觉反馈，首次任务联调建议用实时摄像头。

```powershell
& .\run.ps1 -Mode human-task -ScriptArgs '--video','D:\your-data\pick_place.mp4','--timeout','60'
```

离线模式在视觉对齐、闭爪、抬升等辅助阶段暂停消费示范时间，避免机器人尚未抓稳，
视频就已经走到张手。它是任务阶段对齐回放，不是原时间轴完整自由动作复现。

无摄像头的可重复软件检查：

```powershell
& .\run.ps1 -Mode human-task -ScriptArgs '--check','--scripted-check'
```

此命令明确使用模拟手势输入，报告始终标记 `synthetic_input=true`，
`human_validation_performed=false`。即使物理任务 PASS，也不计为真人示范成功或真人训练数据。
它验证控制逻辑、动力学、任务判定和记录管线，不替代真人测试。

## 结果、检查与回放

输出另存 `openarm_cloth/outputs/human_task/<时间>/`，不覆盖已有记录：

| 文件 | 用途 |
|---|---|
| `manifest.json` | 来源、模型/代码哈希、单位、索引、时钟与图像配置 |
| `episode.npz` | 同步观测、目标动作、实际控制量、人体输入、阶段、动作来源与积分状态 |
| `images/<camera>/<帧号>.png` | 本帧动作执行前的胸部/右腕 RGB，320×240 |
| `scene.mjb` | 当次完整 MuJoCo 模型快照；读取要求同版本 MuJoCo |
| `events.json` | 每次阶段切换的时间与原因 |
| `result.json` | 控制器结果和独立物理评估；失败、取消也保留 |
| `quality_report.json` | 帧数、形状、有限数、时间、图像、模型哈希及来源标签检查 |

`action_target` 是 18 维绝对关节目标（臂 rad、手指 m）；`ctrl` 的臂列为力矩，不能混用。
`evaluation_next` 是执行后的评估专用物体真值，不得作为学习观测或控制输入。
`physics_state` 也包含完整仿真状态，只用于恢复和验证，不应整段作为 BC 输入。
这是独立的 `openarm_human_task_v1` 格式，没有假称旧毛巾录制器已经升级到 v3。

```powershell
# 把路径替换为控制台打印的本次记录目录
& .\run.ps1 -Mode human-task-validate -ScriptArgs '--recording','outputs\human_task\YOUR_RUN'
# 状态回放：查看实际记录，支持原生三维旋转/缩放，空格暂停，Q 退出
& .\run.ps1 -Mode human-task-replay -ScriptArgs '--recording','outputs\human_task\YOUR_RUN'
# 动作回放：从初始状态用 B 执行器重新执行，比较全轨迹，不逐帧强行纠正状态
& .\run.ps1 -Mode human-task-replay -ScriptArgs '--recording','outputs\human_task\YOUR_RUN','--execution','actions','--check'
```

状态观看不等于物理重执行。动作重执行只声称同机、同模型、同 MuJoCo 版本的结果，
跨平台确定性需要另验。回放报告按新时间保存，不改写原任务报告。

独立物理成功要求：抬升超过 3 cm 且双指接触持续至少 0.5 秒；释放后在目标区内、
接近桌面支撑高度、无夹持接触且速度稳定至少 0.5 秒。控制器的阶段成功不能单独产生 PASS。
接触和稳定时间在每个 0.5 ms 物理子步评估，20 Hz 数值记录单独采样。
默认任务时限 15 秒。无窗口自动检查使用仿真控制时间，真人窗口使用扣除主动暂停的墙钟；
二者不能混成实时延迟或真人 15 秒成功率。

## 技术参考与这次选择

2026-10-21 查阅官方源码/文档后采用以下设计思想，未引入其整个框架或替换 B：

- [robosuite Device](https://github.com/ARISE-Initiative/robosuite/blob/master/robosuite/devices/device.py)
  区分相对动作、目标位姿和实际位姿。本项目保留相对手腕映射，并限制目标超前距离，
  控制权切换后从实际状态重建锚点。
- [robosuite 示范数据文档](https://robosuite.ai/docs/algorithms/demonstrations.html)
  保存模型、状态及动作，区分状态回放和动作回放，并明确跨机动作重放可能漂移。
  本项目增加 MJB、积分状态与两种回放；没有把强制设置状态当物理成功。
- [LeRobot 录制流程](https://github.com/huggingface/lerobot/blob/main/src/lerobot/scripts/lerobot_record.py)
  明确观测、处理、动作执行与记录的对应关系。本项目把图像、状态和目标动作绑定到
  同一个物理 tick，并独立记录人的意图和视觉辅助的控制来源。
