# 人控制遮挡上抬与抓取防误触

本次针对两项现场反馈：目标不可见时不再自动上升，以及进入范围但人未明确闭合时误启动抓取。
后续按用户要求已删除范围内“张开右手准备”提示及等待：靠近时自然张手，在后台记录，进入范围直接捏合即可。
运行入口不变：

```powershell
& 'D:\openpi\启动共享抓取.ps1'
```

## 当前操作

1. SPACE 开始一次，移动右手控制机械臂靠近。
2. 方块被遮挡时，向上移手控制张爪上抬。目标高度按当前测得的手部位移和正常增益计算，
   不再一次触发后自动升满 7 厘米。手停止移动时不增加上抬目标；手部失效则保持。
3. 新视野恢复后自动回到普通跟随。靠近时保持手自然打开，进入范围看到绿色“可以抓取”后直接捏合，无需额外张手准备或等待。
   二维与三维指尖距离都确认闭合至少 0.2 秒、至少三个新源帧后，才发起一次抓取。
4. 抓牢后继续移手搬运；张手约 0.35 秒请求支撑放下。上一轮放置修复保留，不要求再次捏合准备释放。

恢复视野阶段只允许有界向上退出：沿既有固定水平位置，上抬目标最多距开始位置 7 厘米，
机器人仍有速度、目标超前量和非加深接触检查。该上限是保护范围，不是自动运动目标。
手部丢失超过 0.35 秒或暂停后重建局部参考，防止恢复识别时突然追赶旧位移。
使用的旧目标几何最多 30 秒，仅供这个退出检查；抓取必须重新取得完整 RGB-D 观测。
普通水平/前后运动在视野恢复后继续。抓取确认后的自动提起仍属于已经请求的抓取流程。

## 定位到的问题

- 原先看到一次张手就全程保留准备状态；`_gesture` 的旧闭合标签还可能在中间开度下残留。
  这样，在范围外闭合或旧闭合未清除时，进入范围就可能沿用旧状态启动抓取。
- 原手部连续夹爪开度用了二维、三维保守融合，但共享抓取的 `intent_ratio` 只由三维距离产生。
  两条通道的定义不一致：连续开度仍显示有缝，自动抓取入口却认为已经闭合。
- 新建共享专用 `shared_grasp_intent.py`，只修正抓取请求。原人体识别、掌深度、手部连续开度和张手释放通道保持不变。

最新录像 `outputs/shared_grasp/20261027_200356_468942` 的四个原抓取请求帧：

| 帧 | 原三维意图值 | 新双通道保守值 | 新值是否达到 0.35 闭合门限 |
|---|---:|---:|---|
| 179 | 0.150 | 0.465 | 否 |
| 577 | 0.150 | 0.443 | 否 |
| 1152 | 0.150 | 0.590 | 否 |
| 2369 | 0.314 | 0.731 | 否 |

这些值证明两路信号不一致，不能据此推断录像中所有真实手势的准确标签。
新规则会拦住这些原始请求帧；这是输入样本审计，不是反事实新机器人轨迹或真人成功率。

## 已加入的门控

- 靠近过程中的新鲜张手观测会在后台记录，不要求在范围内重新张手或停留。进入范围、视野完整且留有原来 4 厘米中心高度余量时，新捏合可以请求抓取。
- 范围外已经闭合的手、旧闭合标签、半开状态、缺失二维指尖尺度、重复帧均不能单独启动抓取。
- 张手靠近时跨越范围或短时视野边界不丢弃自然张手状态；范围外已经捏合、暂停或较长输入中断会清除旧捏合证据。
- 不再因为目标被遮挡时的捏合而进入固定高度的自动上退。
- 界面显示“机械臂随手抬起”和新捏合确认进度；记录 `shared_grasp_request_ratio`。删除额外张手准备后的交互版本为 6。

证据目录 `outputs/manual_view_pinch_20261027/`：

后续流畅入口的独立验证存放于 `outputs/fluent_pinch_20261027/`：旧实现的范围外自然张手后立即捏合用例失败，新实现相关 64 项检查通过。
该版 1000 控制帧连续测试包含两个完整物理成功试次，数据检查通过，旧“张开右手准备”提示出现帧数为零。

- `before_regression.log`：旧实现六项用例中五项失败，覆盖旧闭合、双通道冲突及固定 7 厘米上退。
- `related_final.log`：61 项相关检查通过，包括新捏合、失效/重复帧、手动抬起和放置回归。
- `full_tests.log`：600 项检查，3 项跳过，其余通过。
- `manual_up.json`：从真实遮挡接触物理状态初始化，仅注入软件手部输入。
  按正常增益应上抬 28 毫米，实际 28.78 毫米；最后两秒高度范围约 0.47 毫米，零运动警告、零抓取请求。
- `request_audit.json`：保存两段真人输入的请求帧对照，不改写原失败录像或其标签。
- `continuous/`、`action_replay.log`：1000 控制帧、328 条 RGB-D，两个完整物理成功试次；
  第三轮按帧数预算保存为中断。执行器动作回放 PASS，qpos/qvel 最大差均为 0；合成输入不计作真人示范。
- `saved_release.json`：上一轮失败放置状态的释放回归，结果单独写在本目录。
- `verification.json`：冻结识别/掌深度/原手部连续开度/执行器/基础 B 实现的哈希检查与数据质量结果。

这些检查不保证视觉模型永不误判。当前只处理已知红方块桌面仿真，下一次真人操作需验证新手势入口是否既减少误触又足够方便。
