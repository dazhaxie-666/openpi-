# 坐站切换、手腕观测门控与标定状态反馈

2026-10-22。针对右臂 `human-task --mapping wrist` 在坐姿可用、站立后保持的反馈。本轮修正可确认的软件问题，不宣称已经解决所有站姿单目漏检。

## 两个独立问题

G/O 标定只拟合拇指—食指距离与夹爪开度，不能让摄像头识别画面之外的手臂。最近一次会话的闭合、张开各 10 个试次已经采到，但个人 profile 没有通过，继续使用通用端点：被标为 closed 的距离反而持续大于 open。没有保存原始人体录像，不能断言是按键与动作标反，还是指尖检测错误；不会自动交换标签作为有效标定。

坐站切换方面，旧流把 `position_point` 和手部身份关联也绑定在完整肩—肘—腕门控上。即使手腕、双肩可靠，肘部遮挡/出画仍会把小工作区末端位置控制一起关闭。这与该模式只需要手腕位置的要求不符。

最近一次记录同时有真正的人体检测丢失、手腕低置信度和坐标参考不可用。因为旧记录没有人体图像及二维关键点，无法给每一段坐站姿势作独立标注，也不能证明修改将恢复所有原来被保持的帧。

## 修改

- `body_hand_consistency` 默认继续要求完整肩肘腕；增加明确的 `require_elbow=False` 位置门控，仍要求当前双肩/手腕高置信、在画面内、与可信手部位置一致。
- `BimanualHumanStream` 分别输出完整臂与手腕位置的可信度/原因。完整 A 肩肘腕映射仍在缺肘时保持；手腕位置控制和手指关联不再被不相关的肘部状态阻断。没有降低检测门限或使用旧手位置冒充新观测。
- 双肩或手腕出画仍保持；任务区分 `WRIST_OUT_OF_FRAME`、`SHOULDERS_OUT_OF_FRAME`、`BODY_HAND_WRIST_DISAGREEMENT` 与低置信度，不再全部显示笼统的参考不可用。
- 个人标定严格相反时报告 `OPEN_CLOSED_LABELS_REVERSED`，不自动翻转端点。live/task 界面明确显示 `CALIBRATION READY` 或 `NOT READY` 及原因，10/10 不再被当作通过提示。
- 新任务记录包含二维人体关键点、位置/完整臂分别拒绝的原因、个人配置路径和标定状态，方便后续检查入画边界。原始失败记录不改写。

## 下一次操作

1. 先决定站姿还是坐姿操作，并调整摄像头高度/俯仰或距离，让该姿势的头、双肩、右手腕及完整手指都能清楚入画。右手先放在胸前偏侧的舒适位置，不要自然下垂到画面之外。
2. 用新个人文件，避免继续向错误标签的试次中累加：

```powershell
Set-Location -LiteralPath 'D:\openpi\latest\openpi--main'
& .\run.ps1 -Mode human-task -ScriptArgs '--mapping','wrist','--gripper-mode','continuous','--no-images','--calibration','calibration/personal_motion/standing_pinch_v2.json'
```

3. 先观察 `WRIST_OK`。如果仍是出画、低置信或人体未检测到，先调整取景/姿势；G/O 和 C 都不能恢复不存在的观测。
4. G：拇指与食指指尖接触；O：两指分开。姿势先稳定，再按对应键并保持约 2 秒，等待本次试次计数增加。交替各至少 10 次，最终检查 `READY`。`NOT READY: LABELS REVERSED` 不能继续当作成功使用。
5. 正常张开手指，空格/START 开始。切换坐站后先恢复 `WRIST_OK`，在运行中按 C 重定操作中心。C 不会清空夹爪个人端点，也不等同于相机重新识别或标定成功。
6. Q 正常退出。只有有效个人配置才写入指定的全局个人文件；每次会话的试次与失败原因另存于本地 `personal_calibration.json`。

如果新版本在头、双肩、手腕、手指都完整入镜的站姿仍漏检，需要进一步检查新的二维位置/拒绝原因；可选 `--save-human-video` 只在本地保存人体录像，便于逐帧核验。不要仅靠把置信度一降再降来填补不可观测的位置。
