# 真人记录异常退出及手部误关联修复

针对 `outputs/a_live/20261021_201727_608885/`，保留原失败录像与数据。
本轮依据实际 191 行控制记录、153 帧录像排查，没有访问新摄像头，也没有上传私人录像。

## 两个独立原因

1. **退出原因已复现**：将保存的不同源帧依次送入 A 原控制器，源帧 219 左臂第 3 关节
   输出 `1.5707999999999505`，B 上限为 `1.570796`，相差约 `0.000004 rad`。
   A/B 限位的小数取舍不同，原 B 接口容差只有 `0.000001 rad`，于是抛出 ValueError。
   这不是 TensorFlow 初始化警告引发的退出，也不是必须扩展机械臂物理限位。
2. **人体与手部误关联**：图像中存在肘腕漂移到胸腹部的情况。另有一帧在身体手腕可见性
   仅 0.293 时，仍接受了距离对应身体手腕约 706 像素的手部检测；正常可见帧中也有超过
   170/210 像素的关联。旧逻辑在当前手腕缺失时，允许通过旧位置或左右手标签继续分配。
   手模型的 handedness 分数表示左右手类别可信度，不能证明衣服或身体上的检测就是可靠手部。

复现脚本及结果：`outputs/a_live/diagnose_user_exit_20261021.py`、
`outputs/a_live/user_exit_diagnosis_20261021/probe.json`。
原始失败瞬间的输出发生在控制步之前，未写入下一行；因此使用最后保存的人体源帧重算复现，
没有将记录中的末行关节命令冒充为已经保存的异常命令。

## 实现

- 新增 `live_observation_quality.py`。A 到 B 的关节接口只对 `1e-4 rad` 范围内的小数舍入误差
  投影到 **B 原有限位**；更大的越界、非有限值或畸形参考只让对应一侧保持并记录原因。
  另一侧继续，不因识别产生的单侧异常直接结束程序。真正的 MuJoCo 非有限状态仍是运行错误。
- 修复动作和桌面任务两条 A 参考路径的同类边界问题；原 A 映射、IK、标定源码未重写。
- 新增关节/夹爪限位前的制动距离约束，包含物理步积分余量。大幅动作到边界前逐渐减速，
  避免平滑器自身越过 B 限位后再硬截断造成速度跳变。测试先复现约 0.00146 rad 的原轨迹超调。
- 默认人体模型由 `lite` 改为 `full`。保留显式 `--pose-model lite` 作对照。
- 手部必须关联当前帧可见的身体手腕，使用像素尺度及肩宽自适应距离；
  取消缺失时按标签或历史位置直接分配，保留左右一一对应和重复检测去重。
- 检查手部 21 点有限性、画面边界、掌部退化/尺度；新出现或重新捕获的手需两个不同观测确认。
  手部缺失继续保持连续开度，不自动张开。
- 两只独立可用手部检测与身体手腕明显不一致时，屏蔽不一致侧的身体参考。
  低可信侧也不再为下一帧手部 ROI 提供胸腹位置，独立全画面搜索继续恢复检测。
- 可信度结果贯穿摄像头流、A 最新帧工作线程和控制端，旧手腕消费者也不能继续使用已拒绝的点。
  原始人体/手部关键点保留用于诊断，不用猜测的深度替换肩肘腕。
- HUD 显示身体保持原因和左右手 `confirmed / HOLD`；不可信身体连线为灰色。
  记录新增对应原因字段，避免看起来无故卡住。
- 参考加速度按 400 Hz 更新，常加速度段在每个 B 物理步求位置/速度，B 电机仍按原 2 kHz 工作。
  减少与识别线程争抢 CPU 的小数组运算，本机短测控制计算中位耗时由约 36.1 降至 21.2 ms；
  两次短测的机器负载不同，仅作性能检查，不称端到端摄像头延迟保证。

## 同一段视频的模型对照

在同一组 153 帧保存图像上分别重新运行人体模型。统计“可见身体手腕到最近已保存手部检测的
像素距离”，只是几何一致性指标，不是带人工标注的准确率；也不是端到端相机延迟。

| 人体模型 | 手腕分歧超过 100 px 次数 | 推理中位耗时 | 推理 P95 |
| --- | ---: | ---: | ---: |
| lite | 48 | 11.7 ms | 13.4 ms |
| full | 13 | 16.0 ms | 17.8 ms |
| heavy | 11 | 64.8 ms | 98.0 ms |

本机选择 full 作为准确性与响应折中；heavy 的收益不足以抵消该次测试中的耗时。
证据在 `user_exit_diagnosis_20261021/body_model_comparison*.json`。

## 验证

- 先写六项失败测试，复现微小限位差退出、非有限参考退出、缺失身体仍按手标签分配、
  170 像素误配，以及可信度拒绝未传到 A 等问题；修复后通过。
- 完整 B 回归 313 项：310 通过、3 项权限跳过。之后补充限位前制动回归并重跑相关 71 项，全部通过。
  日志：`outputs/a_live/user_exit_full_regression_20261021.log`、`user_exit_final_targeted_20261021.log`。
- 用真实 `BimanualHumanStream`、A 映射、B 动力学类，仅将 USB 读取替换为保存的录像输入，
  153/153 帧全部走完，无异常、机器人状态有限，目标关节未超 B 范围。
  第一轮：左/右可信身体 97/90 帧，确认手部 92/85 帧。录像前 50 帧多有肘腕画外或低置信度，
  两侧没有被错误地当作可控身体；这部分是明确的保持，不是跟随成功。
  最终修改后重执行结果保存在 `outputs/a_live/user_pipeline_recheck_20261021_release/report.json`；
  中间检查的 `_final` 等目录也保留。
- 纯软件动作检查验证记录结构，不能代替真人验收。

此次复验覆盖了用户提供的原失败记录。新逻辑仍是基于模型与几何的检测，并不保证所有遮挡、
衣服图案或近距离画面都能正确识别；本轮没有宣称新真人摄像头验收已经完成。

## 操作

```powershell
Set-Location -LiteralPath 'D:\openpi\latest\openpi--main'
& .\run.ps1 -Mode live
```

现在默认 full，无需加参数。让头部、双肩、肘和手腕同时进入画面，先稳定等待每侧 10 个有效帧标定。
过近导致肘腕画外时，应退后或调整镜头；无需让机械臂根据身体部位猜测手的位置。
灰色连线/`HOLD` 表示当前该侧观测未获确认，原因会显示；手重新被确认后自动继续。
左右身份仍为人体解剖左右，镜像仅改变预览；Q 保存退出，C 重新标定。
